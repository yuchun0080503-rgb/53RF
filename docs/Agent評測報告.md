# ResearchFlow Agent 評測報告

依競賽辦法附件二「決賽 Agent 評測最低揭露項目」整理。最後更新：2026-11-10。

## 1. 評測設計

| 項目 | 內容 |
|---|---|
| 任務 | 給一張小組白板（學生寫下的 2–3 句想法），Agent 從頭跑完：判斷範圍 → 聚焦提問 → 研究問題 → 規劃關鍵字 → 搜尋證據（最多 3 輪，含反思與放寬條件）→ 逐篇判讀 |
| 任務成功的判定 | 最後至少有 1 篇支持、1 篇反向／限制，而且總共 ≥ 3 篇（正反例證模式的最低要求） |
| 測試案例 | 40 題，分兩組：**原本 20 題**（`tools/eval/cases.json`，開發時用來調整提示詞）、**保留題 20 題**（`cases-holdout.json`，調整提示詞時沒有看過，用來檢查是否只對特定題目有效）。題目涵蓋教育、心理、健康、社科、媒體、職場 |
| 每題的參考關鍵字 | 每題預先寫好 4–6 個學界常用的英文術語，用來算關鍵字命中率 |
| 測試環境 | 正式網站 https://researchflow-3dd2c.web.app ，瀏覽器內執行與網站相同的程式；AI 經 Firebase Cloud Function；聚焦提問模擬學生只回答白板上寫到的條件 |
| 模型 | Claude Haiku 5.5（`claude-haiku-5-5`） |
| 評測程式 | `tools/eval/run-eval.mjs`（Node 版）與瀏覽器版（同一套步驟） |

### 2.2 與基準方案比較（原本 20 題）

| 方案 | 任務成功率 | 關鍵字命中率 | 平均延遲 | 說明 |
|---|---|---|---|---|
| 規則式（不用 AI，11/07） | 100% | 33.5% | 4.4 秒 | 不判讀文獻，查到什麼都算數，所以成功率高但混入大量不相關文獻 |

| **Claude Haiku 5.5（11/08）** | **65%** | **68.5%** | 30.6 秒 | 當時 OpenAlex 沒有金鑰，後段被擋；也還有「摘要被切掉」的問題（已修正） |
| **Claude Haiku 5.5，保留題（11/10，最新版）** | **75%** | **68.0%** | 53.8 秒 | 加入多資料庫分流、中文文獻網路搜尋、OpenAlex 金鑰 |

人工流程對照：在試用回饋表中請使用者比較「以前找到 3 篇可用文獻花的時間」與「這次花的時間」（收集中）。

### 2.3 成本

正式環境每天記錄 AI 用量（Firestore `aiUsage`）。2026-11-10 全天（含本次評測、組員測試、提示注入測試）：AI 呼叫 520 次、輸入 165 萬 token、輸出 23 萬 token、網路搜尋 83 次。

依價格估算（Claude Haiku 5.5 輸入每百萬 token 0.10 美元、輸出 0.50 美元；網路搜尋每次約 0.01 美元）：
- 全天約 1.1 美元，其中約 0.8 美元是中文文獻的網路搜尋。
- **一題（一組學生跑完一次完整流程）約 0.04–0.06 美元**，主要成本是中文網路搜尋。
- 全站每日上限 2000 次 AI 呼叫，約 100–130 次完整流程。

## 3. 錯誤分類（保留題沒成功的 5 題）

| 題目 | 支持／反向／待確認 | 類型 | 說明 |
|---|---|---|---|
| h18 戶外教學與學習興趣 | 10／0／0 | 單一方向 | 找到的研究都支持，沒有反向證據；依設計交給小組決定是否另找反面例證 |
| h04 學習障礙學生用平板 | 0／1／2 | 文獻少＋摘要沒寫結果 | 相關研究少，多數摘要只寫方法，列為立場待確認 |
| h08 多益分數與就業 | 0／1／3 | 文獻少＋摘要沒寫結果 | 同上 |
| h12 數學焦慮與習得無助 | 0／3／2 | 主張方向 | 找到的研究多指出條件限制，沒有直接支持 |
| h07 網路霸凌與心理健康 | 0／10／3 | 立場方向判斷 | 10 篇都被判為反向；初步看起來是「研究問題是問句」造成方向判斷困難，待逐篇檢查 |

先前版本（11/08）發現並已修正的錯誤：
1. **摘要被切掉**：判讀時只給模型摘要前 650 字，研究結果在摘要最後面，模型判斷不出立場、被歸成反向。改成 2400 字後，同一批論文支持證據從 0 篇變 7 篇（s06）、0 篇變 5 篇（s14）。
2. **判斷不出立場的被放進反向**：新增「立場待確認」一欄，請學生讀原文。
3. **AI 自造關鍵字**（例：post-exercise learning 在論文標題出現 0 次）：已加入學界正式名稱的規則；關鍵字查證（用論文數量確認）已完成邏輯，待接入。
4. **OpenAlex 沒有金鑰被擋**：同一網路一天約 100 次。改由後端代理帶金鑰，本次 0 次被擋。
5. **同一篇論文從兩個資料庫重複出現**：改用 DOI 去重複。
6. **某個資料庫不回應，整個搜尋卡住超過 5 分鐘**（本次評測第 14 題發生）：每個外部請求加上逾時（一般 25 秒、中文網路搜尋 75 秒），逾時的來源當作失敗、其他結果照常使用。

## 4. 已知限制、最壞情境與回復方式

| 情境 | 系統會怎樣 | 回復方式 |
|---|---|---|
| Claude 連不上或達到每日上限 | 每一步改用規則式，畫面標示「AI：未連線（規則式）」 | 自動；隔天重置或調高上限 |
| OpenAlex 被擋或代理失效 | 改直接連線，再不行改查 Crossref | 自動 |
| 某個資料庫一直不回應 | 等到逾時後略過那個來源 | 自動 |
| 3 輪後證據仍不足 | 停止自動搜尋，提示小組修改方向或關鍵字（人工介入） | 學生決定 |
| AI 判讀錯誤 | 所有分類標示為初步，學生可改列；摘要沒寫結果的列為待確認 | 學生確認 |
| 中文文獻只有摘要片段 | 標示「來源待驗證」，請學生開原文 | 學生確認 |

## 5. 可查核的執行紀錄（trace 範例：保留題 h03）

白板：「護理師輪班會讓身體變差？／夜班／職業倦怠」

| 步驟 | 結果 |
|---|---|
| 研究問題 | 護理師輪班工作（特別是夜班）如何影響其身體健康與職業倦怠程度？ |
| 關鍵字規劃 | 主題詞：shift work、burnout、nurses；觀點詞：night shift、physical health |
| 選用資料庫 | 依學科（醫護）自動加查 Europe PMC；OpenAlex（經後端代理）；華藝／臺灣博碩士論文網（網路搜尋） |
| 第 1 輪搜尋＋逐篇判讀 | 10 篇：支持 6（含華藝 3 篇中文文獻）、反向／限制 4 → 達成目標，停止 |
| 時間與呼叫 | 48.5 秒，17 次外部呼叫，全部成功 |

網站上每份研究另有「研究歷程」分頁，逐筆記錄每一步的時間、執行者（學生或 Agent）、使用的資料庫與判讀結果，評審可以直接在網站查看。

## 6. 版本管理
- 程式與提示詞都在 GitHub，經 Pull Request 合併；提示詞集中在 `src/agent-llm.mjs`、`functions/zhsearch.js`。
- 評測題目與程式在 `tools/eval/`，每次修改提示詞後重跑並比較。

## 7. 安全測試
提示注入與不當輸出測試（5 項，全部擋下），見《資料與安全自評表》五之一。
