## 一、讀程式碼時發現、會影響規格的事

| # | 發現 | 影響 |
|---|---|---|
| F1 | **MIN_LEVEL 目前只在瀏覽器檢查。** `db.mjs` 的 `guard()` 在前端呼叫 `harness.mjs`；後端 `functions/proxy.js` 的 `makeCheck` 只檢查「是 owner／editor」和「Level ≥ 1」，請求裡沒有「動作」欄位。 | 規格要求「伺服器端檢查、從後端直接呼叫也會被拒絕」，現在做不到，要改 Function。 |
| F2 | **提示詞和 JSON 格式都由瀏覽器送出。** 後端只是轉送 `system`／`user`／`schema`。 | 就算後端檢查動作名稱，改過的前端也能填假的動作名稱，或自己寫提示詞要求逐字稿。要真的擋住「完整講稿」，排演室的提示詞和格式要放在後端，由後端組裝；輸出格式也要限制每點的字數。 |
| F3 | **沒有規則測試的環境。** 專案沒有 `@firebase/rules-unit-testing`，這台電腦也沒有 Java（Firestore 模擬器需要 Java）。 | 「組員讀不到學號」的規則測試需要先安裝 Java（免費）和模擬器。 |
| F4 | **分工任務沒有截止日。** `tasks` 只有 `title, type, assigneeUid, createdBy, createdAt, done, doneBy, doneAt`。 | T2「分工任務逾期 ≥ 3 天」需要新增 `due`。 |
| F5 | **作業沒有「報告日」和「報告時間（分鐘）」。** 作業只有 `{id, title, req, due}`。 | S3 的時間配額、T2「報告日前 2 天」需要新增欄位。 |
| F6 | **沒有「已讀」紀錄。** 老師回饋和指定閱讀都沒有記錄「我開過了沒」。 | S1「未讀回饋／未開啟閱讀」需要記錄每個人的已讀時間。 |
| F7 | **留言圖釘只有兩種狀態：`open`／`done`。** | T2「留言待結案」需要老師的「結案」狀態。 |
| F8 | **報告沒有「已批改」標記。** 老師對 project 只能改 `aiLevel`。 | T2「報告待批改」的消失條件需要「已批改」。 |
| F9 | **`users/{uid}` 只有本人讀得到；`members/{uid}` 全組都讀得到。** | 學號不能放在這兩處，要另外開一個只有本人和老師讀得到的位置。 |
| F10 | **「超出權限・已阻擋」是畫面依歷程文字判斷的**（`k:'sys'` 且內容含「拒絕」），沒有獨立欄位。 | T2「AI 反覆被阻擋」先沿用這個判斷；之後新寫的阻擋紀錄加上 `blk:true`，判斷比較穩。 |
| F11 | 現有網址參數只有 `?code=`、`?join=`，**沒有深層連結。** | 需要新增 `?p=<專案id>&tab=…`。 |

## 二、新增／修改的資料欄位（沿用現有集合，不另起一套）

| 位置 | 新增欄位 | 用途 | 規則變更 |
|---|---|---|---|
| `users/{uid}` | `sid`, `sidAt` | 學號本體與修改時間（個人檔案設定） | 不用改（本人讀寫） |
| `users/{uid}` | `seen: {<pid>: {fb, rd, rubric}}` | 已讀時間：老師回饋、指定閱讀、評分配比版本 | 不用改 |
| `users/{uid}` | `snooze: {<待辦key>: 恢復時間}` | 稍後提醒（換裝置也同步） | 不用改 |
| **新** `courses/{cid}/roster/{uid}` | `sid, sidAt, name` | 學號給老師看的副本 | 新規則：本人可寫；本人與該課老師可讀；組員讀不到 |
| `courses/{cid}` | `requireSid: bool` | 課程是否必填學號 | 不用改（老師可改課程） |
| `courses/{cid}.assignments[i]` | `rubric: {ver, at, items:[{name, pct, desc, to:'all'｜'speaker'｜'maker'}]}`, `rubricHist: [...]`（最多保留 10 版） | T1 評分配比與舊版本 | 規則只擋「非老師不能改」；合計 100% 的檢查放在 `rubric.mjs` 和儲存前（Firestore 規則無法加總陣列） |
| `courses/{cid}.assignments[i]` | `talkDate`（YYYY-MM-DD）, `talkMin`（分鐘） | 報告日、報告時間 | 不用改 |
| 課程沒有作業清單時 | 課程本身的 `rubric`／`talkDate`／`talkMin` | 同上，與現有 `teacherReq`／`dueDate` 的做法一致 | 不用改 |
| `projects/{pid}/tasks/{tid}` | `due`（選填，建立時填） | 分工任務截止日 | 建立時多允許 `due`（字串、YYYY-MM-DD） |
| `projects/{pid}/members/{uid}` | `deckSeenUrl`, `deckSeenAt` | 講者按「已看過簡報」；簡報連結換了就要重看 | 本人可改的欄位多加這兩個 |
| `projects/{pid}/pins/{id}` | `status` 多一種 `closed` | 老師結案 | 只有老師能設 `closed` |
| `projects/{pid}` | `gradedAt` | 老師標記「已批改」 | 老師可改的欄位：`aiLevel` 之外多加 `gradedAt` |
| **新** `projects/{pid}/nudges/{key}` | `kind, text, to:[uid], by, uid, at` | 老師「提醒同學」；文件 id 由事項決定，24 小時內不能重寫 | 新規則：只有老師能寫；`at` 必須是伺服器時間；距離上次 < 24 小時就拒絕 |
| `projects/{pid}/researchState/rehearsal` | `{json, updatedBy, updatedAt}` | 排演室最近一次的結果（全組共用） | 允許的 docId 多加 `rehearsal` |
| `projects/{pid}/feedback/{id}` | `kind:'rehearsal'` | 老師在排演室的要求，顯示「老師要求」標籤 | 不用改（現有規則沒有限制欄位） |
| `projects/{pid}/agentTrace` | `blk:true`（新紀錄才有） | 被阻擋的紀錄 | 不用改 |

**講者／製作者的判斷**（`rehearsal.mjs`）：講者是被指派 `present` 任務的人；製作者是被指派 `poster` 或 `research` 任務的人。同一人可以兩者都是。

## 三、其他假設

1. **「Agent 等你確認」**：研究狀態停在 `STEPS[1]` 確認理解或 `STEPS[4]` 確認策略，而且組裡至少有我一位 owner／editor（老師、viewer 不列）。
2. **「小組多日沒更新」**：沿用現有的「需要注意」規則，`tIdle ≥ 3` 天。規格的「標記持續 ≥ 3 天」我解讀成同一件事；如果要的是「標記出現後再過 3 天」（等於 6 天沒更新），請告訴我。
3. **「尚未選作業」**：課程有作業清單，但這份研究沒有 `assignmentId`。建立研究時一定會選組，所以「沒選組別」只會出現在舊資料，照列。
4. **「截止日倒數」用作業的 `due`**（沒有就用研究的 `dueDate`）。「講者未看簡報」用 `talkDate`，沒設定就不出現。
5. **老師提醒何時消失**：系統每次重新判斷，原本的狀況不再成立，學生和老師兩邊的項目都自動消失，不需要另外寫「已解決」。
6. **時間**：「今天」「明天 9:00」一律用台灣時間（與 `course.mjs` 的 `endOfDayTW` 一致）。
7. **Kahoot 匯出**：實作時到 Kahoot 官方說明頁確認範本欄位（題目、4 個選項、作答秒數、正確答案）再做，不憑印象猜。
8. **排演室的 Level 0–1**：只顯示準備度檢查和手動計時器，不呼叫 Agent。
9. **評分配比**：規則無法檢查合計是否為 100%，前端和 `rubric.mjs` 會擋，但改過的前端仍能存進不合法的配比。學生端讀到不合法的配比時，顯示「配比設定有誤，請洽老師」。這一點會寫進 README 的已知限制。
